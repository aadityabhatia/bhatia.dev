Build Durable Artifacts

Package and share your creations!

Sonny Bhatia

Thursday, November 12, 2026

Motivation: throwaway artifacts do not scale

  • Single-use scripts - disposable by design

  • PowerPoint decks are hard to version and maintain

  • Reusable code helps others, including the future you

  • Goal: artifacts others can easily reach, run, and extend

  • Example: an MS thesis website instead of scattered decks and repos

Why? Credit and Continuity

  • Build things that outlast a semester or two
  • Others get value from your work; you get the deserved credit
  • Reproducibility starts with code someone else can run
  • Durable tools compound
    • “I can just vibecoding this when I need”

What deserves publishing?

  • Is this a one-off answer, or a method others might need again?
  • Who is the audience: you in two years, students, collaborators, community?
  • Would someone else rebuild this? Publish it.
  • Name it, document it, make it easy to reach and easy to run.

Micropublications

Small, self-contained artifacts published as you go - not one monolith at the end.

  • Publish at the size of the idea
    • A function, a worked example, a working tool
  • Release often
    • Each unit is something others can find, run, and build on
  • Low cost per unit, repeated over time
    • Many small artifacts compound
  • Collect them in one place so the body of work grows!

Shareable knowledge graph

Notes, code, data, and demos linked into one structure others can traverse and query.

  • Every artifact is a node
    • links connect topics, prerequisites, and people
  • Add metadata (front matter) so the collection is traversable and queryable
  • Build it incrementally: each linked micropublication strengthens the graph

Four Layers of Publishing

  • Package (PyPI): code others can install and extend
  • Author (Quarto): documents that stay in sync with code
  • Host (GitHub Pages): a site that updates itself on every push
  • Connect (knowledge graph): linked artifacts others can traverse and query

Quarto: setup once, update often

  • Quarto is a technical publishing system
  • Input: Markdown + LaTeX
  • Output: all major formats via pandoc - HTML, PDF, slides, DOCX
  • Dynamic documents: code and prose in one source, regenerated automatically
  • Interactive dashboards and websites, books, and more
  • Everything is Markdown: version control and multiple contributors

Course materials

  • Notes, labs, and assignments, versioned in git
  • Interactive slides and examples students can run
  • Auto-rebuild on push - the course site stays current
  • Share the repository with students; use AGENTS.md to guide their LLM tutors

PyPI: Packaging for Reuse

  • pip install focus-feed instead of “here is a zip and good luck”
    • or even better: uvx focus-feed
  • Releases and dependencies in one place
  • Others can build on your API
  • Discoverability: reach a larger audience
  • Have your agent draft the release workflow
  • Watch the maintenance contract - releases, issues, API stability

Software Licenses

MIT

  • Permissive; closed derivatives allowed
  • Keep the copyright and license notice
  • Fewest conditions, widest adoption

Apache 2.0

  • MIT plus explicit patent grants
  • Extra clauses: notices, trademarks
  • Patent protection for company code

SSPL

  • Source-available, not OSI open source
  • Network copyleft: SaaS must publish source
  • Blocks cloud strip-mining; less adoption

GPL and family

  • Copyleft: derivatives must stay GPL
  • GPLv2/v3 plus AGPL for network services
  • Guarantees downstream stays open

GitHub Pages

  • Free static hosting for docs, course sites, and demos
  • GitHub workflows build and deploy the site for you
  • Your pages stay current without manual uploads
  • Develop a personal website in under 20 minutes!

Start with one artifact

  • Pick one script or micropublication someone else would find useful
  • Add a README and a license
  • Publish to your personal Git location or github.com/usma-eecs
  • Link it into your knowledge graph and drop the link at usma-eecs/awesome!
